# Goodreads Insights Web App — Project Plan

## Context
Build a full-stack web app to analyze a Goodreads library export CSV and display reading insights visually. The user is building this to learn SQL and AI/NLP. Stack: FastAPI (Python) + PostgreSQL + React. Single-user, no auth. Possible Azure deployment. Mobile-responsive UI with a share/export feature.

---

## CSV Structure (confirmed)
Key columns from `goodreads_library_export.csv`:
- `Book Id`, `Title`, `Author`, `Additional Authors`
- `ISBN`, `ISBN13`
- `My Rating` (0-5), `Average Rating`
- `Publisher`
- `Number of Pages` -- used for pace + longest/shortest. Goodreads exports the edition's page count;
  Kindle editions use a normalized estimate (~266 words/Kindle location). All 319 rows in sample
  have values, none zero. Small variance vs. print is acceptable for trend analysis.
- `Binding` -- NOT USED (not everyone marks format; inconsistent)
- `Year Published`, `Original Publication Year`
- `Date Read`, `Date Added`
- `Bookshelves` -- NOT USED FOR GENRE (inconsistent across users)
- `Exclusive Shelf` (read / to-read / currently-reading)
- `My Review`, `Read Count`, `Owned Copies`

Genre source: Fetched from external APIs post-upload using ISBN:
- Primary: Google Books API -- https://www.googleapis.com/books/v1/volumes?q=isbn:{isbn}
  -> `categories` field (clean high-level genres, no key needed)
- Fallback: Open Library API -- https://openlibrary.org/api/books?bibkeys=ISBN:{isbn}&format=json&jscmd=data
  -> `subjects` field (also used for book covers)

---

## AI Approach
Use Gemini Flash (cheapest tier, free: 15 RPM / 1M TPD) + aggressive DB caching.
Generate AI content ONCE per upload, store in DB, serve cached on subsequent visits.
No per-book API calls. HuggingFace runs on-server (free, no per-call cost).

## Database Schema

-- books table
CREATE TABLE books (
    id                SERIAL PRIMARY KEY,
    goodreads_id      INTEGER UNIQUE,
    title             TEXT NOT NULL,
    author            TEXT,
    additional_authors TEXT,
    isbn              TEXT,
    my_rating         SMALLINT,           -- 0 = not rated
    avg_rating        NUMERIC(3,2),
    publisher         TEXT,
    num_pages         INTEGER,
    year_published    SMALLINT,
    original_pub_year SMALLINT,
    date_read         DATE,
    date_added        DATE,
    exclusive_shelf   TEXT,               -- 'read', 'to-read', 'currently-reading'
    my_review         TEXT,
    read_count        SMALLINT DEFAULT 1,
    owned_copies      SMALLINT DEFAULT 0
);

-- genres (fetched from Google Books / Open Library by ISBN after upload)
CREATE TABLE genres (
    id    SERIAL PRIMARY KEY,
    name  TEXT UNIQUE NOT NULL            -- e.g. 'Fantasy', 'Fiction', 'Romance'
);

-- many-to-many
CREATE TABLE book_genres (
    book_id   INTEGER REFERENCES books(id) ON DELETE CASCADE,
    genre_id  INTEGER REFERENCES genres(id) ON DELETE CASCADE,
    PRIMARY KEY (book_id, genre_id)
);

-- AI reader summary cache
CREATE TABLE reader_summary (
    id           SERIAL PRIMARY KEY,
    library_hash TEXT UNIQUE,             -- hash of library state
    summary_text TEXT,
    created_at   TIMESTAMP DEFAULT NOW()
);

## Build Phases

### Phase 1 -- Database & Backend Foundation
Goal: PostgreSQL running, FastAPI connected, models defined

1. Create PostgreSQL database (goodreads_db) locally
2. Write backend/app/database.py -- SQLAlchemy async engine
3. Write backend/app/models/book.py -- ORM models matching schema above
4. Write backend/app/main.py -- FastAPI app with CORS
5. Run Alembic migrations to create tables
6. Add .env with DATABASE_URL, GEMINI_API_KEY

SQL learned: CREATE TABLE, PRIMARY KEY, FOREIGN KEY, ON DELETE CASCADE

---

### Phase 2 -- CSV Upload & Parsing
Goal: Upload CSV -> clean data with Pandas -> insert into PostgreSQL -> kick off genre enrichment

1. backend/app/services/csv_parser.py:
   - Read CSV with Pandas
   - Clean: strip ISBN formatting (="..." -> clean string), parse dates, handle missing ratings
   - Bookshelves column ignored for genres
   - Return structured list of dicts
2. backend/app/routers/upload.py -- POST /upload accepts multipart file
3. Upsert books into DB (handle re-uploads gracefully)
4. After insert, trigger background task (fastapi.BackgroundTasks) to fetch genres per book via ISBN

SQL learned: INSERT ... ON CONFLICT DO UPDATE (upsert), bulk insert patterns

### Phase 2b -- Genre Enrichment Service
Goal: Async ISBN -> genre lookup, stored relationally

1. backend/app/services/genre_service.py:
   - fetch_genres_for_book(isbn: str) -> list[str]
   - Try Google Books first -> volumeInfo.categories
   - Fallback to Open Library -> subjects[].name
   - Normalize: title-case, deduplicate, filter noise
   - Skip if book already has genres in DB (idempotent on re-upload)
2. Upsert into genres + book_genres tables
3. If ISBN is missing for a book, skip gracefully

SQL learned: INSERT ... ON CONFLICT DO NOTHING, multi-table upsert pattern

---

### Phase 3 -- Insights API
Goal: Raw SQL queries returning JSON data for charts

Write query functions in backend/app/services/insights.py using SQLAlchemy Core (raw SQL):

- GET /insights/books-per-year    -- COUNT by year from date_read
- GET /insights/genres            -- JOIN books -> book_genres -> genres, COUNT per genre
- GET /insights/ratings           -- distribution of my_rating values
- GET /insights/top-authors       -- GROUP BY author, COUNT DESC LIMIT 10
- GET /insights/reading-pace      -- SUM(num_pages) GROUP BY year/month
- GET /insights/heatmap           -- books per month, all years (calendar heatmap)
- GET /insights/summary           -- aggregate stats: total books, total pages, avg rating

SQL learned: GROUP BY, COUNT, SUM, AVG, ORDER BY, LIMIT, EXTRACT, JOIN, WHERE

---

### Phase 5 -- AI Features
Goal: Low-cost AI features safe for public deployment

Cost strategy: Gemini Flash + aggressive DB caching. One generation per upload, cached in DB.

#### 5a. "What kind of reader are you?" blurb (Gemini Flash)
- GET /ai/reader-summary -- one call per library upload
- Input: top genres, avg rating, books/year, favourite authors, re-read count, longest book read
- Example: "You're a voracious romantic at heart -- devouring fantasy worlds by night and
  swooning over slow-burn romances by day."
- Cache in reader_summary table (keyed by hash of library); regenerate only on new upload
- UI: highlight card at top of dashboard, also included in share PNG

AI learned: Prompt engineering, context window design, caching strategy

#### 5b. Book recommendations (Gemini Flash)
- POST /ai/recommendations -- sends top-rated books + top genres to Gemini Flash
- Returns 5 personalized recommendations with reasons
- Cached in DB; UI: card list with book cover via Open Library (free, no key)
- Regenerated only on new upload

AI learned: Few-shot prompting, structured output parsing

#### 5c. NLP -- Review sentiment (Hugging Face, free, runs on server)
- Use transformers sentiment pipeline on user reviews -> "mood over time" line chart
- Zero API cost, runs on server
- Only processes reviews that exist (skip blanks)

NLP concepts learned: Tokenization, sentiment classification pipelines

---

### Phase 6 -- Share / Export Feature
Goal: Generate a shareable PNG summary card

- PNG only: use html2canvas in browser to capture a dedicated summary card component -> download
- Summary card includes: total books read, top genres, avg rating, reader-type blurb, year badge
- Example: "Helen read 47 books in 2025 * Top genres: Fantasy, Romance * Avg rating: 4.2"
- No server-side generation (no reportlab dependency)
